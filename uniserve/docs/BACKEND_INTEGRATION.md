# Backend integration

Source of truth: the supplied Express backend (`routes/`, `controllers/`, `models/`, `middleware/`).
Base URL comes from `VITE_API_URL` (default `http://localhost:4000/api`). Auth is `Authorization: Bearer <jwt>`; tokens last 1 hour and there is no refresh endpoint.

## Contract map

| Frontend use                  | Endpoint                          | Guard                            | Payload / query                                                               | Response shape                                    | Status                                                |
| ----------------------------- | --------------------------------- | -------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------- | ----------------------------------------------------- |
| Login                         | `POST /auth/login`                | public                           | `{ email, password }`                                                         | `{ token, user: { id, username, email, role } }`  | Integrated                                            |
| Register                      | `POST /auth/register`             | public                           | `{ username, email, password }`                                               | same as login; role is forced to `studentOrstaff` | Integrated                                            |
| Session restore               | `GET /auth/me`                    | auth                             | –                                                                             | `{ user: { id, username, email, role } }`         | Integrated                                            |
| Forgot password               | `POST /auth/forgot-password`      | public                           | `{ email }`                                                                   | `{ message }` (always 200)                        | Integrated                                            |

| Own / assigned / all requests | `GET /requests`                   | auth                             | – (unpaginated)                                                               | `{ count, requests[] }`                           | Integrated (client-side search, filter, sort, paging) |

| Admin request details         | `GET /admin/requests/:id`         | admin                            | –                                                                             | `{ request }`                                     | Integrated                                            |
| Request history               | `GET /admin/requests/:id/history` | admin                            | –                                                                             | `{ history[] }` (oldest first, `actor` populated) | Integrated                                            |
| User list                     | `GET /admin/users`                | admin                            | `page, limit, role, status=active\|inactive, search`                          | `{ pagination, users[] }`                         | Integrated                                            |
| Single user (workaround)      | `GET /users`                      | admin                            | –                                                                             | `{ users[] }` (all users)                         | Used because `GET /admin/users/:id` is missing        |
| Change role                   | `PATCH /users/:userId/role`       | admin                            | `{ role }`                                                                    | `{ user: { id, … } }`                             | Integrated (note path is not under `/admin`)          |

Status transitions enforced by the backend: `active → in-progress | cancelled`, `in-progress → completed | cancelled`; completed and cancelled are final.
Who may do what: start/complete → assigned officer or admin; cancel → request owner or admin (officers cannot cancel); a completion note is required (≤1000) when completing and forbidden otherwise.

## Backend issues found while integrating

1. **Login does not check `isActive`.** A deactivated user still receives a token, and every later call returns 403. The frontend clears the session when `/auth/me` returns 403, but the user sees no explanation. Reject deactivated accounts at login with a clear message.
2. **`GET /admin/dashboard/officers` only lists officers who already have assignments.** An officer with no requests would never appear in an assignment picker, so the frontend builds that list from `GET /admin/users?role=maintenanceOfficer`.
3. **`GET /admin/requests` search is not regex-escaped** (`adminController.getAllRequests`), unlike the user search. Escape it.
4. **Inconsistent identifiers and error keys.** Auth responses use `user.id`, list responses use `_id`; errors arrive as `message` or `error`. The API client normalises both.
5. **Role changes are not protected against removing the last admin**, and existing JWTs keep working until expiry.
6. `controllers/studentAndstaffController.js` duplicates `requestController.js` and is unused. Two different `getAllUsers` exist (`/users` and `/admin/users`).
7. The uploaded archive contained a `.env`. If it held real credentials, rotate them.

## Features the backend supports that the UI does not expose

`PATCH /requests/:id` (owner edits an active request), `DELETE /requests/:id` (owner soft-deletes a cancelled request), `PATCH /auth/change-password`. They were outside the specified screens.
